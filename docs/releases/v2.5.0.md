# v2.5.0 更新说明

v2.5.0 集中更新了账号迁移、登录、线路、状态检测和机器人通知。下面记录的是当前实现的最终行为；部分功能在开发期间经过调整，旧 PR 中的中间方案不代表本版本的操作方式。

## 新增：Xray 订阅与每账号独立线路

- 镜像内置 Xray-core。进入**系统设置 → 机场订阅**，填写 HTTPS 主订阅；可再填写兜底订阅并手动刷新。支持已实现的 Clash 兼容 YAML 和节点 URI 格式，具体协议与构建要求见 [Docker 部署指南](../deploy/docker.md#机场订阅与-xray)。订阅 URL 是凭据，应妥善保管。
- 每个健康节点最多分配给一个账号：先使用主订阅的空闲节点，再使用兜底订阅的空闲节点；节点总数不足或全部不可用时，剩余账号**直连**。直连账号可能共用服务器的公网出口 IP。已测得重复公网出口 IP 的节点会尝试重新分配；尚未测得出口 IP 时先按节点去重。
- 节点每 **5 分钟**检测一次；首次超时、连接失败或超过延迟阈值后 **1 分钟**复检，连续 **2 次异常**才切换。初始延迟阈值为 **800 ms**，可在设置中调整。优先订阅的节点恢复后，连续 **2 次正常**才回切。订阅文档每 **60 分钟**刷新，也可手动刷新。
- 账号卡片的 **IP 定位**仅显示出口国家，下方显示公网出口 IP；标题旁显示**主订阅 / 兜底订阅 / 直连**。定位服务失效时显示未知，不将节点服务器地址冒充出口 IP。换线路会重新连接，但不会删除 Telegram 或 TeleBox 授权；仅授权本身被 Telegram 判为无效时才需要重新登录。
- 旧版手填 SOCKS5 配置不再控制账号连接。首次配置订阅前账号显示“待配置”，不会因旧 SOCKS5 地址而连接或静默直连。

## 新增：账号登录备份和更明确的验证码流程

- 在**账户管理 → 登录备份**手动导出密码加密的 `.tglogin` 文件，迁移到新服务器后导入。文件只包含已授权主账号的 Telegram 会话及其 API ID/Hash；**不包含**面板设置、订阅、TeleBox 授权或数据、备注、状态和消息历史。同名账号在导入时跳过。导出需要输入至少 12 字符的密码，并分别确认旧服务器停用和新服务器恢复的迁移事项；确认不会自动停止容器。详见[登录备份与恢复](../guide/account-login-backup.md)。
- 手机验证码登录会提示 **Telegram 实际采用的送达方式**、可用的下一送达方式和重发倒计时。无需选择短信或应用渠道；送达由 Telegram 决定。可重发时沿用当前登录会话，按 Telegram 提供的后续方式请求；若 Telegram 未提供后续方式，界面会提示检查现有设备或改用二维码。普通账号也可以使用二维码登录。
- 迁移前先备份完整 `data/`，并在新服务器使用同一授权前停止旧服务器。`.tglogin` 是主账号登录资料的补充迁移工具，不能替代整目录备份；TeleBox 使用独立授权，迁移后按需重新登录。不要让两台服务器同时使用同一份会话，以免授权失效。

## 新增：零点报告与私人 Bot 命令

- 按系统设置的时区，每天 **00:00** 启动一次全部账号状态和节点线路检测；默认时区为 UTC+8。配置并启用 Bot 通知后，同一流程读取各主账号收到的 Telegram 官方服务号 `777000` 在**前 24 小时**内的消息，完成后推送汇总。账号多、消息多或遇到限流时，推送可能在零点之后完成；错过零点不会在其他时段补跑完整报告。
- 每个账号的汇总行显示账户状态、当前**主订阅 / 兜底订阅 / 直出**线路，以及“无官方新消息 / 有官方新消息”。任一检测异常或出现官方新消息时使用红色图标；有消息时另发完整文字和可转发的媒体/附件。读取失败不会写成“无新消息”。Bot 未配置或通知关闭时仍进行账号状态检测，但跳过官方消息读取与推送。详见[账号与消息指南](../guide/accounts.md#每日官方消息报告)。
- 私人 Bot 新增 `/me`，列出自然排序的账号编号、名称和备注；随后可用 `/code 4` 或 `/code 账号名` 按需查询该账号**最近 5 分钟**的验证码。只有配置的私人目标 ID 可用；**相同的完整指令**有 **45 秒**冷却，不同指令可连续发送。空闲时不扫描账号消息。
- 系统设置中的“测试机器人连接”只发送一条测试消息。原“完整检测并推送”手动按钮已移除，不能用连接测试触发零点报告。

## 调整：手动检查范围与界面

| 入口 | 执行内容 | 触发方式 |
| --- | --- | --- |
| 账号卡片下方的“检测状态” | 仅检查这一账号的 Telegram 状态、TeleBox 状态和当前出口 IP | 手动 |
| 账户管理的“批量检测” | 检查所选账号的上述状态，并以服务器可靠的登录会话清单为准，清理孤立账号元数据和对应 TeleBox 数据 | 手动 |
| 每日 00:00 作业 | 检查全部账号与线路；Bot 已配置时再读取前 24 小时官方消息并推送 | 自动定时 |

手动单检、批检都不会读取官方消息或发送完整报告。仪表盘可见时约每 30 秒刷新已保存的结果，这不是新的 Telegram 检测。账号卡片菜单移除了重复的“检测”和单账号“日志”入口；TeleBox 运行日志页面与通用设置里的手动保活入口也已移除。TeleBox 错误仍记录在经过脱敏的服务器日志中。

## 调整：资源使用

节点探测最多同时运行 **6** 个请求；账号列表同时加载可见头像最多 **2** 路，头像 Object URL 缓存总量限 **2 MiB**，替换或离开页面时回收旧 URL。服务日志与错误缓冲、头像请求状态也设置了边界，减少长期运行时缓存和内存持续增长的风险。账号和 TeleBox 仍各自使用独立会话；启用更多 TeleBox 账号仍会增加进程及实际负载，应按部署规模监控资源。相关变更见 [PR #65](https://github.com/hikling/TG-Manage/pull/65)。

## 部署与升级

1. 新安装按[快速开始](../guide/quick-start.md)执行；已有部署在原仓库目录运行 `bash scripts/update.sh`。脚本会停机备份、快进拉取、重新构建并启动。不要删除或重新初始化现有 `data/`。
2. 核对完整 `data/` 备份，特别是隐藏文件 `data/.app_secret_key`、数据库、主账号会话、`xray/` 与 TeleBox 目录。外部数据库需单独备份。需要跨服务器迁移主账号授权时，再使用“账户管理 → 登录备份”的 `.tglogin` 导出/导入；该文件不替代完整部署备份。
3. 升级后在“设置 → 机场订阅”填写或检查主、兜底订阅，确认可用节点与账号卡片上的线路、国家和出口 IP。旧 SOCKS5 配置不再生效；直连是节点不足或失效后的明确兜底状态，可能暴露服务器出口 IP。
4. 如需零点报告，检查系统时区、Bot Token、私人目标 ID 与 Bot 通知开关，并用“测试机器人连接”验证发信。报告只会在下一次零点作业完成后发送。可手动用单检或批检验证账号状态，但不会提前生成报告。

当前文档与自动化检查覆盖代码及静态资源行为；**本次文档整理未在这台 Windows 交接主机上完成真实 Linux Docker/Xray、外部订阅和 Telegram 账号的端到端联测**。升级后请在自己的服务器验证订阅可用性、出口 IP、账号授权、TeleBox 与 Bot 实际送达。
