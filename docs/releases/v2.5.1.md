# v2.5.1（2026-10-22）

本版本把零点订阅、账户和官方消息检查整理为一条日报，并在通知机器人私聊中增加“打开WEB”入口。

## 新功能与调整

- 每天 00:00 按面板时区刷新主订阅及兜底订阅，并在日报中列出各来源的可用和不可用/不支持节点数。若刷新失败，报告会说明沿用上次节点状态。
- 零点账户状态异常时自动复检。仍异常且属于线路可恢复问题时，尝试另一个可用出口 IP 节点并再次检测；无合适备用节点、需重新登录或最终仍异常时，在日报中说明。
- 将“零点账户状态与官方消息日报”和“零点机场订阅节点报告”合成一份摘要，账户在上、节点在下，两处标题加粗。Telegram 消息长度限制可能使摘要分段，官方消息详情仍可单独发送。
- 通知设置新增机器人 Web 地址，为指定的私人目标 ID 设置“打开WEB”聊天菜单。Telegram Mini App 的签名和用户 ID 会在后端验证，成功后签发短时面板会话；其他用户不能通过这个入口登录。已有的 <code>/me</code> 和 <code>/code</code> 命令仍受私人取码开关和目标 ID 限制。
- 补强容器启动时数据目录权限处理，避免受限挂载卷上的 chmod 失败导致容器反复重启。

## 升级

在现有仓库目录运行：

~~~bash
bash scripts/update.sh
docker compose ps
docker compose logs --tail=100 app
~~~

更新脚本会先备份，再拉取代码并重建容器。务必保留整个 <code>data/</code>，包括 <code>data/.app_secret_key</code>。服务显示 <code>Up</code> 后，打开面板检查版本、账号和订阅状态。

如需“打开WEB”，到“设置 → Telegram 机器人通知”填写 Bot Token、**正整数的私人目标 ID** 和可供 Telegram 访问的 **HTTPS 网站根地址**，例如 <code>https://example.com</code>，然后保存。菜单仅设置在该目标用户的私聊中。Bot Token 或目标 ID 变更后，旧入口会失效。公网网址本身不会绕过普通管理员登录。

## 验证重点

1. <code>docker compose ps</code> 中应用容器保持 <code>Up</code>，面板能正常打开。
2. 手动刷新机场订阅后，主订阅和兜底订阅的状态及节点数正常显示。
3. 在通知目标用户的私聊中看到“打开WEB”，点击后能进入面板；其他用户无法获得面板授权。真实 Bot API 菜单同步需要在部署环境验证。
4. 下次 00:00 检查合并日报：账户部分在前、节点部分在后，两个标题加粗；异常账户展示复检或换线结果。

有关订阅分配、手动检测范围和登录备份，参见 [v2.5.0 更新说明](v2.5.0.md)。
