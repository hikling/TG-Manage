# 设计

## 代码边界

- 前端：删除 `Workbench.vue` 和路由/导航/专属 CSS；`Bots.vue` 作为系统设置内的分区，复用原有 API 与鉴权。仪表盘复用 `/api/ops/memory`，间隔轮询，不叠加请求，页面销毁时清理。
- 后端：现有 `/api/ops/memory` 已提供 `current_rss_mb`，优先复用。重命名自有 Python 包 `tg_signer` → `tg_manage` 与引用；保留原有数据目录和旧环境变量的读取入口，并以新名称作为文档与新写入默认值。
- 部署：镜像/容器可改名，但 Compose 的 `./data:/data` 和密钥文件保持稳定，升级脚本不删除卷。自动/手动备份清单继续包含旧数据路径。
- GitHub 版本检查默认仓库及所有 UI 跳转改为私有仓库；无 Release 时应有可理解的反馈，不破坏页面。

## 数据迁移

新内部键在读取时先查新值，再查旧值；写新值时保留旧值或提供一次性安全迁移。长期保存的账号/会话/密钥目录保持可发现。任何重命名文件的升级都应先复制或原子移动，并在目标存在时不覆盖。

## 验证

静态搜索旧标识及工作台引用，逐项区分兼容键、历史记录、第三方版权与遗漏；运行现有单元测试、类型检查和构建。视觉审查优先代码支持的桌面/移动断点，再按可用浏览器环境检查。
