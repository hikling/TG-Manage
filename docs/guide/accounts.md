# 账号管理

## 支持的登录方式

TG-SignPulse 当前支持三种常用登录流程：

- 短信验证码登录
- 二维码登录
- 账号启用了 Telegram 2FA 时补交密码

所有登录流程都通过后端 `accounts` API 完成，登录状态会被保存到数据目录中。

## 账号字段建议

- `账号名称`：建议使用稳定、易识别的名称，例如 `main_cn`、`backup_01`
- `手机号`：短信登录时使用
- `代理`：可选，适合账号需要单独走代理的场景
- `备注`：用于在面板里区分账号用途

## 代理规则

系统同时支持“全局代理”和“账号级代理”。

优先级：

1. 账号单独配置的代理
2. 全局设置中的 `global_proxy`
3. 未配置代理时直连

常见格式：

```text
socks5://127.0.0.1:1080
socks5://user:pass@127.0.0.1:1080
http://127.0.0.1:7890
```

## 二维码登录流程

1. 在面板发起二维码登录
2. 用 Telegram 手机端扫描
3. 如果 Telegram 返回 `password_required`，继续填写 2FA 密码
4. 登录成功后会自动落盘会话

适合：

- 不方便接收短信验证码
- 批量维护已有账号

## 会话存储模式

通过环境变量 `TG_SESSION_MODE` 控制：

- `file`：默认模式，使用会话文件
- `string`：使用 session string 存储

### file 模式

适合大多数场景。

- 会话更直观
- 与传统 Telegram 客户端管理方式一致
- 数据落在 `sessions/` 目录

### string 模式

适合容器化或你希望统一管理 session string 的场景。

- 账号信息保存在 `sessions/accounts.json`
- 对迁移和备份更友好

## 聊天中心与消息读取

聊天中心左侧入口始终显示，页面内的开关默认关闭。关闭时，该页只读取 Telegram 官方验证码账号 `777000` 的消息；聊天会话、消息、媒体和头像的读取接口会拒绝请求。账号工作台仍可按目标 ID 或用户名发送消息并建立每日定时消息任务。

在“聊天中心”开启聊天后，可浏览群组对话和头像。聊天列表与消息的前端缓存超过 5 MB 会强制清理，本地聊天头像缓存超过 5 MiB 也会清理。TeleBox 是账号独立的插件运行时，启用的插件仍会按自身规则处理 Telegram 更新。

## 账号状态检测

面板支持检查账号状态。`status` 常见取值：

- `connected`：会话可用
- `invalid`：会话失效
- `error`：检测过程出错
- `checking`：检测进行中

另有独立布尔字段 `needs_relogin`：为 `true` 时表示需要重新登录（常见于 `status = invalid`）。

建议：

- 定期检查长期挂机账号
- `needs_relogin` 或 `invalid` 后尽快重登
- 如果任务失败集中出现在某个账号，先检查账号状态和代理

## 重新登录

当账号失效或 Telegram 要求重新验证时：

1. 打开账号编辑
2. 保留原账号名称
3. 使用短信或二维码重登
4. 成功后以账号名称绑定的 TeleBox 任务及每日消息任务仍可使用；若插件命令发生变化，需重新选择已加载命令

## 账号专属 Telegram API

新增或重登账号时可以勾选“启用 TeleBox”，这时填写该账号专属 API ID/Hash；成功登录后自动请求独立会话。不勾选时登录页面不用填写，但服务器私有 `.env` 需事先设置 `SIGNPULSE_TG_API_ID/HASH`，因为 SignPulse 本身也要用 Telegram API 授权。授权成功后凭据按账号加密保存，后续聊天、任务和监听从账号读取。旧账号若提示缺少凭据，请重新登录同名账号。系统设置页不暴露这些值。

## 建议做法

- 一个账号只承担一类核心任务，便于排障
- 风险高的任务单独走代理
- 每个 TeleBox 插件任务选择一个账号；工作台每日消息可以选择多个账号
- 长期运行时定期备份 `sessions/` 与数据库
