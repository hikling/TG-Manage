# 功能介绍

TG Manage 的主要入口如下。运行要求和安装方法见 [README](../README.md)；新增功能、检测时序与迁移边界见 [v2.5.0 完整更新说明](releases/v2.5.0.md)。

| 入口 | 功能 |
| --- | --- |
| 仪表盘 | 展示可自定义封面、账号与 TeleBox 数量、正常账号数量、服务内存和需要关注的账户；可见时每约 30 秒读取已保存的账号检测结果，不触发额外检测。 |
| 账号管理 | 手机验证码或二维码登录；按账号启用 TeleBox、查看状态、设备，以及当前 Xray 线路的 IP 定位。每个健康节点只分配给一个账号，依次使用主订阅、兜底订阅，多出的账号直连；线路检测与账户状态检测分别运行。账户管理的“登录备份”可手动导出或导入加密的主账号 `.tglogin` 授权文件。 |
| 聊天中心 | 按需开启群组会话，查看与发送消息、附件；关闭时仅在授权的 `/code` 请求下读取指定账号的官方验证码消息。 |
| 系统设置 → 机器人通知 | 仅指定私人 ID 可用 `/me` 查看编号、账号名称与备注，再通过 `/code 4` 按需查询第 4 个账号最近 5 分钟的验证码，也支持 `/code 账号名`；重复同一完整指令须间隔 45 秒，不同指令可连续发送，空闲时不读取账号消息。“测试机器人连接”只发测试消息。 |
| 零点官方消息报告 | 每天 00:00 检测全部账户及过去 24 小时的官方消息，逐账户汇总账号、当前线路和有无新消息；有消息的账户另推送完整文字与附件。仅定时运行，其他时间不触发完整报告。 |
| 系统设置 | 管理主订阅、兜底订阅、延迟阈值和通知；通用设置说明零点自动检测规则，不提供手动保活。登录备份入口在账户管理，不在系统设置。 |

## v2.5.0 重点变化

- **账号线路：**镜像内置 Xray；HTTPS 主订阅和可选兜底订阅向账号分配独占节点。节点不足或全部失效后多出的账号直连，直连账号可能共用服务器公网 IP。IP 定位只显示国家，下方显示实际公网 IP，标题旁标明线路来源。旧手填 SOCKS5 不再生效。
- **节点健康：**每 5 分钟检测，首次异常 1 分钟后复检，连续两次异常才切换；初始延迟阈值 800 ms，可调整。回切需连续两次健康检测，订阅每 60 分钟刷新，并在设置时区的每天 00:00 再刷新一次。
- **检测边界：**卡片单检只看当前账号 Telegram、TeleBox 和 IP；手动批检检查所选账号，并清理服务器孤立元数据及 TeleBox 数据。每日 00:00 全局检测中，异常账号会复检；仍异常时尝试切换空闲健康节点并再次检测，最终结果进入账号、线路和前 24 小时官方消息报告。
- **账号迁移与登录：**“账户管理 → 登录备份”提供加密 `.tglogin` 导入/导出；文件不含 TeleBox 或面板配置。手机验证码的实际送达方式由 Telegram 决定，界面显示送达提示和重发倒计时，重发沿用登录会话。
- **界面与资源：**移除卡片菜单重复检测/日志入口、TeleBox 运行日志页和手动保活；IP 探测、日志缓冲、头像请求状态设置上限。

TeleBox 每个运行中的账号使用独立进程与会话，插件由 TeleBox 自身管理。面板不缓存每账号进程日志；异常写入脱敏的服务日志。历史签到、监听和 AI 任务不会自动执行；升级不会自动清除其持久数据。参见 [无损升级说明](deploy/docker.md#无损升级与回退)和[版本详解](releases/v2.5.0.md)。
