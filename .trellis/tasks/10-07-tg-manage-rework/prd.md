# TG Manage 品牌与面板整理

## 目标

将项目的对外和自有内部名称统一为 TG Manage；精简导航，展示实时进程内存，修复实际 UI、响应式与无障碍问题；提供不丢失现有网站数据的更新说明。

## 已确认的需求

- 页面标题、PWA、文档、部署名称、下载名称、项目自有 Python 包和配置标识改用 TG Manage。用户明确要求内部标识一起迁移。
- 升级时现有账号、Telegram 与 TeleBox 会话、数据库、设置、机器人资料、备份均可继续读取。旧标识需要兼容或迁移，不得通过清空数据目录解决。
- 移除账号工作台页面、导航、路由、页面专用样式和关联代码。现有聊天中心与机器人消息能力继续可用。
- 机器人中心归入系统设置，不再作为独立顶级导航。
- 仪表盘定期显示当前服务进程 RSS，写明统计范围和更新时间；失败时显示可理解的状态。
- 所有 UI 中指向 GitHub 的操作链接指向 `hikling/TG-SignPulse-Private`，并更新页面名称。
- 使用 ui-ux-pro-max 检查键盘、触控、移动布局、对比度、状态反馈并修复发现的问题。
- Markdown 说明如何从此私有仓库更新代码、备份整个持久化数据目录与密钥、保持原挂载重建、升级后验证。区分更新与恢复，不使用删除数据的步骤。

## 验收标准

- [ ] 运行界面不再出现旧品牌、工作台顶级入口或工作台页面；机器人功能可从系统设置访问。
- [ ] 新包名和自有标识可用；旧持久化路径/键升级后仍可读取，且没有自动删除数据。
- [ ] 仪表盘内存显示来自当前进程的周期刷新，错误/不可用状态明确，卸载后停止轮询。
- [ ] GitHub 导向链接均指向用户私有仓库。
- [ ] 桌面和移动布局、亮暗主题、键盘焦点与可读标签通过代码检查及可运行的前端验证。
- [ ] 相关 Python 检查与前端类型检查、测试、构建通过；缺少 Docker 或真实 Telegram 会话的验证如实记录。

## 边界

- TeleBox vendored 上游源码、协议名与许可仍按其原名保留。
- 旧历史任务/数据文件保留用于恢复，不因页面删减而清理。
- 当前工作副本来自私有仓库 `main` 的只读 ZIP 快照 `3dc192f`，没有 Git 元数据；交付需可审查源码包和变更清单。
