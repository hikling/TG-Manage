# 快速开始：TG Manage

## 准备

服务器需要 Docker Engine 24+、Docker Compose v2、Git，以及连接 Telegram 和下载构建依赖（包括 Xray 官方归档）的网络。TeleBox 账号需要自己的 Telegram API ID/Hash。先了解 [v2.5.0 的功能与迁移边界](../releases/v2.5.0.md)。

## 安装

```bash
git clone https://github.com/hikling/TG-Manage.git
cd TG-Manage
bash scripts/install.sh
```

安装脚本从源码构建镜像、启动容器、等待 `/readyz` 就绪，并输出一次性管理员设置码。打开 `http://服务器IP:8080`，用设置码创建至少 12 位的管理员密码。已有部署会保留原管理员密码。

不启用 TeleBox 的普通账号也可使用服务器自己的 Telegram 应用凭据：在私有 `.env` 中设置 `TG_MANAGE_TG_API_ID` 和 `TG_MANAGE_TG_API_HASH`。旧版 `SIGNPULSE_TG_API_*`、`TG_API_*` 在升级时继续读取。

## 开始使用

1. 在“设置 → 机场订阅”填写 HTTPS 主订阅，可再填兜底订阅，刷新后确认出现可用节点。每个节点只分配给一个账号；主、兜底节点不足的账号会直连，可能共用服务器出口 IP。没有配置过订阅时账号网络处于「待配置」，旧版手填 SOCKS5 不再生效。详见 [Xray 与订阅说明](../deploy/docker.md#机场订阅与-xray)。
2. 在“账号管理”用手机验证码或二维码登录账号；验证码实际送达方式由 Telegram 决定，页面会提示渠道及重发倒计时，无需先选短信或应用。需要 TeleBox 时填写该账号专属 API ID/Hash。
3. 在账号卡片查看主会话、IP 定位和 TeleBox 的独立状态；“IP 定位”仅显示出口国家，下方是公网出口 IP，标题旁是主订阅、兜底订阅或直连。出现两步验证提示时按页面要求补交密码。单检和批检共用每账号成功后 45 秒的检测间隔。
4. 在“聊天中心”按需开启聊天，先用自己的测试对话验证消息收发。
5. 如需私人机器人，在“系统设置 → 机器人通知”填写 Bot Token 和正整数的私人目标 ID，启用后仅该 ID 可以用 `/me` 查看编号、账号名称和备注，再发 `/code 4` 查询第 4 个账号最近 5 分钟的官方验证码，也支持 `/code 账号名`。重复同一条完整指令须间隔 45 秒，不同指令可以连续发送；空闲时不轮询账号消息。“测试机器人连接”只发送测试消息。
6. 按需点击账号卡片的“检测状态”检查**当前账号**的 Telegram、TeleBox 和 IP，或手动使用“批量检测”检查所选账号并清理服务器孤立元数据/TeleBox 数据。这两种手动操作都不读取官方消息。每天按系统时区 00:00 自动检测全部账号和线路；启用 Bot 通知时还读取前 24 小时的官方消息，完成后推送报告。完整报告不能手动触发。
7. 需要迁移主账号登录时，在“账户管理 → 登录备份”手动导出密码加密的 `.tglogin`，新服务器安装后再导入。先停用使用同一授权的旧服务器；文件不含面板设置或 TeleBox 授权，操作前读 [登录备份指南](account-login-backup.md)。
8. 在仪表盘进入账号管理或刷新封面；在自定义主题中选择主题色、上传不超过 1 MiB 的封面并调整水平和垂直位置。设置同步保存到服务器。

## 下次升级

在原仓库目录执行 `bash scripts/update.sh`。脚本会短暂停机并备份整个 `data/`，再拉取当前仓库代码和重建。升级不会清空原挂载目录；请保留数据库、会话、`xray/`、TeleBox 数据和隐藏的 `.app_secret_key`。升级后确认订阅状态、出口 IP 和 Bot 连接；检查与回退步骤见 [Docker 部署与升级](../deploy/docker.md#无损升级与回退)。
