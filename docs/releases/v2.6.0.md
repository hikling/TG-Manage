# TG Manage v2.6.0 更新说明

**发布日期：2026-11-26**

v2.6.0 聚焦三大方向：**现代卡牌式 UI 重构、全仓安全审计与并发逻辑修复、冗余代码与过时依赖精简**，并在不破坏现有 Docker 无损升级路径与 `.tglogin` / 会话持久化数据前提下完成平滑迭代。

---

## 一、UI 视觉与交互全面焕新

1. **账号管理卡牌式布局**
   - 账号卡片升级为 **20 套循环多段炫丽渐变封面栏**，大尺寸头像居中跨线排布，账号名置于横线上方、备注置于横线下方，兼顾辨识度与信息层次。
   - 中段卡片精简聚焦 **IP 定位与代理线路归属**，移除重复的「TeleBox 已停止」文案；底部操作栏直接提供 **TeleBox 启动/停止切换按钮** 与 **检测状态** 按钮，运行中若遇 2FA 验证可直接在卡内输入密码完成授权。
   - 移除卡片上重复的聊天中心入口，将聊天中心统一保留在左侧主导航栏中。
2. **自定义外观与仪表盘封面高度**
   - **仪表盘封面高度调节**：自定义外观弹窗新增封面高度滑块与即时预览，支持服务端保存与多端同步，无需反复裁图即可适配不同比例的封面图片。
   - 同步提供自定义主题强调色（默认 `#3367a6`）与深/浅双模式细节打磨，统一设置页手风琴与聊天中心双栏视觉表现。
3. **聊天中心与 777000 验证码收件箱**
   - 左侧栏直观筛选并切换已登录账号，即使未开启完整聊天模式，仍可直接查看 777000 Telegram 官方安全消息并一键复制登录验证码；开启完整聊天后支持对话搜索、归档切换、消息回复/编辑/撤回以及附件收发。

## 二、全仓安全加固与逻辑修复

### 认证、访问控制与网络边界

- **WebApp 短时会话权限隔离**：新增 `require_standard_admin_user` 依赖，明确禁止通过 Telegram WebApp 入口签发的短时令牌调用修改密码、修改用户名及开启/关闭 2FA 等高敏账户端点。
- **用户枚举计时侧信道与密码长度校验**：未知用户名登录路径补齐常量级 dummy bcrypt 校验；初始化管理员与修改密码接口统一拦截超过 bcrypt 72 字节 UTF-8 上限的输入并返回明确 400 提示。
- **TOTP 与限流边界加固**：修复 TOTP 重放窗清理顺序，改为先清理过期条目再校验，并将 pending secret 操作纳入线程锁保护；`/totp/qrcode` 补充 `Cache-Control: no-store` 与 `X-Content-Type-Options: nosniff`；修复内存速率限制器过期桶未回收、触发封禁后的无效空 deque 残留以及浮点 `Retry-After` 响应头问题。
- **SSRF 与代理订阅解析防护**：`subscription_import` 增加对 NAT64（`64:ff9b::/96` 等）、IPv4-mapped、6to4、Teredo、保留地址及 `localhost`/内网后缀域名的拦截，并在连接 HTTPS 时规范处理 IPv6 `Host` 头部。
- **CORS 与静态兜底安全**：当允许来源包含通配符 `*` 时自动关闭 `allow_credentials`；静态文件解析增加异常处理并对未命中的 `/api/*` 请求明确返回 JSON 404；规范 Vercel `middleware.js` 中的 `Link` 头部域名解析；Server酱推送补全 `sendkey` 字符集校验；Webhook 推送告警日志不再打印包含敏感 URL 的原始异常文本。

### 并发安全、进程隔离与数据一致性

- **`accounts.json` 线程锁与重命名迁移**：为 `backend/utils/tg_session.py` 的全部读取-修改-保存操作加 `_STORE_LOCK` 可重入锁；修复 `rename_account_entry` 在目标已存在时提前 `pop` 旧记录的问题，确保 `export_session_string_from_file` 的 SQLite 连接在异常路径正确关闭；账号重命名提前校验名称与大小写冲突后再停止 TeleBox，并同步迁移离线头像缓存与状态标记。
- **Xray 与 TeleBox 运行时稳定性**：`xray_runtime` 先通过 `fdopen` 写配置再调整文件权限并在 `_validate` 中捕获 `BaseException` 避免孤儿进程；`account_routes` 增加 `min_good_streak` 阈值，防止 `good_streak == 1` 的节点误覆盖主线恢复并补充活跃代次兜底；`telebox.py` 校验 `node_modules` 符号链接、`O_NOFOLLOW` 打开 `runtime.lock`、`shutdown()` 直接温和关闭已启动 worker；`telebox/panel/worker.ts` 改用原子写入 `config.json` 并在运行时启动标志 `runtimeStarted` 为真时才执行关停。
- **时间戳、热路径与 Docker 启动脚本**：`communications.timestamp()` 修复 Naive 本地时间误标为 UTC 导致的 8 小时偏移；`push_notifications._safe_msg_truncate` 修复标签栈清空后末尾残缺 `<tag` 与残缺 `&entity` 截断导致 Telegram HTML 400 报错问题；`docker/entrypoint.sh` 跳过符号链接目标并扩展私钥/路由敏感配置 `chmod 600` 覆盖范围。

### 前端交互与状态竞态修复

- **`accounts.ts` 路径编码与 Store 会话隔离**：`deleteAccount` / `updateAccount` 对账号名执行 `encodeURIComponent` 编码；`useAuthStore.isTokenExpired()` 支持 Base64URL（`-`/`_`）字符解码；`useAccountsStore` 切换/登出 token 时同步重置 `inFlight` 并在旧请求结束时校验代次避免覆盖 `loading`。
- **弹窗生命周期与多层 Esc 栈**：`Modal.vue` 由标量计数器重构为 `modalStack` 数组栈，支持多层弹窗乱序关闭时保持 `Escape` 响应权；`AddAccountModal` 引入同步 `reset()` 与 `sessionGen` 请求代次校验；`DeviceManagerModal`、`OfficialMessagesModal`、`Accounts`、`Chats`、`useAccountBatchCheck`、`useSettingsPage`、`TelegramEntry` 统一补全卸载清理、请求竞态守卫、区域时间格式（`zh-CN` / `en-US`）及文件输入状态复位；`useToast` 在 `resume()` 时同步刷新 `expiresAtMap`，修复「暂停→恢复→再暂停」剩余时间失准问题。
