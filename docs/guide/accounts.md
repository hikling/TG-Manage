# 账号与聊天

## 登录账号

TG Manage 支持手机验证码、二维码和 Telegram 两步验证。登录状态保存在持久化数据目录；重新登录时保持原账号名称，可继续关联原有账号数据。

登录时可为该账号启用 TeleBox，并输入专属 API ID/Hash。未启用 TeleBox 的普通账号可以使用服务器私有 `.env` 中的 `TG_MANAGE_TG_API_ID/HASH`；旧版 `SIGNPULSE_TG_API_*`、`TG_API_*` 仍可读取。授权后的凭据按账号加密保存，不会在账号列表 API 中回传明文。

## 机场订阅与账号线路

在「设置 → 机场订阅」配置 HTTPS 主订阅，可选填兜底订阅和延迟阈值。应用通过 Xray 为每个账号分配独占的健康节点，先用主订阅空闲节点，再用兜底订阅空闲节点；两者仍不足时，多出的账号直连，不共用已分配节点。已测得的重复出口 IP 会触发重新分配；出口 IP 未测得时先按节点去重。连续两次检测超时、连接失败或超过阈值才切换，首次异常会在 1 分钟后复检，常规检测间隔为 5 分钟。节点恢复后连续两次正常检测才回切。详细限制见 [部署指南](../deploy/docker.md#机场订阅与-xray)。

首次配置订阅前账号连接处于「待配置」。账号卡片的「IP定位」只显示出口国家，下面显示实际公网 IP，标题旁标明主订阅、兜底订阅或直连；定位服务不可用时显示未知。旧版手填 SOCKS5 地址不再影响连接。线路切换会让 TeleBox 重新连接，但保留 Telegram 和 TeleBox 授权，不会因此重新索取验证码。

## 聊天中心

聊天中心的开关默认关闭；私人机器人仅在授权的 `/code` 请求下读取指定账号的官方验证码消息，另有下文说明的每日零点官方消息报告。开启聊天后可查看会话、消息与头像，并执行发送、编辑或删除等实际 Telegram 操作。前端缓存有容量上限；长期保存消息应使用自己的备份方案。

## TeleBox 独立会话

TeleBox 不复用主账号的 Telegram 会话。每个启用账号拥有独立的运行目录和 Node 进程；账号卡片显示状态与两步验证要求。停止 TeleBox 进程和退出其 Telegram 登录是两种不同操作。面板不保留每账号进程日志；异常状态显示安全的错误提示，脱敏错误另写入服务器日志。

## 状态与恢复

账号状态检测结果可显示 `connected`、`invalid`、`error` 或 `checking`。出现 `needs_relogin` 时，先确认 Telegram 授权和 API 凭据，再使用原账号名称重新完成授权；单纯线路故障不代表授权失效。迁移或升级服务器时要同时保留 `sessions/`、`telebox/`、`xray/` 和 `.app_secret_key`；见 [无损升级](../deploy/docker.md#无损升级与回退)。

## 每日账户状态报告

服务每天按全局设置中的时区，在 00:00 开始检测账号管理中的全部账号，并更新账号状态。默认时区为 UTC+8，与北京时间一致。检测逐个进行，单个账号失败或超时后会继续检测其余账号；账号较多时，报告会在全部检测完成后发出。

自动全局检测只在每日零点启动，不会在启动服务、打开页面或凌晨 03:30 再次触发。错过零点后不会在其他时间补启动检测；其他时间可自行点击单个或批量检测。零点已开始的检测可以继续完成。

账户卡片下方的“检测状态”只检测该账户的 Telegram 状态、TeleBox 状态和当前出口 IP。账户管理的“批量检测”手动检查所选账户的这些状态，并以服务器上可靠的登录会话清单为准，清理没有对应账户的旧元数据与 TeleBox 数据；不会读取官方消息或向机器人发送完整报告。设置中的“测试机器人连接”只发送一条测试消息。

仪表盘的“正常账号”数量和“需要关注的账户”读取已保存的检测结果。零点检测发现异常后，会显示该账号及异常原因；后续检测恢复正常后会移出关注列表。仪表盘保持可见时，每约 30 秒刷新一次本地状态数据；这一刷新不会连接 Telegram 检测账号，也不会读取验证码历史或下载头像。关注列表预览最多显示 8 个账号，完整列表可在账号管理中查看。

在设置中启用 Telegram Bot 通知并填写 Bot Token、目标 ID 后，机器人会自动推送汇总报告。每个用户名前显示 `🟢`（账户、线路和官方消息检测均正常且无新消息）或 `🔴`（任一项异常，或有官方新消息），并附正常、异常及总账号数。每行包含「账户正常/异常 · 主订阅/兜底订阅/直出 · 无官方新消息/有官方新消息」；没有 Telegram 用户名时显示本地账号名称。较长的报告会分成多条消息。

每日零点报告会在检测完成后发送，即使零点处于通知静默时段。未配置机器人或关闭 Bot 通知时仍检测账号，但不推送。运行服务是执行定时检测的前提；异常表示本次检测未成功，也可能由代理或网络问题引起。

## 每日官方消息报告

同一零点流程还会读取全部主账号在 Telegram 官方服务号 `777000` 中收到的最近 24 小时消息，并通过现有 Bot Token、目标 ID 和话题 ID 推送。范围在零点启动时固定：例如 14 日零点的报告包含 13 日零点起至 14 日零点前的消息。超过这个范围的旧消息和用户自己发给官方服务号的消息不会转发；检测或推送耗时较长也不会把范围向更早历史扩展。

报告不限条数，按页读取直至完成该时间范围。每条消息标注账户、原消息时间和消息编号，保留完整文字和媒体说明；长文字会分条发送。图片、视频和附件下载后通过机器人重新发送，超出 Telegram 单次上传限制的附件按编号分卷，并附原文件名和按编号拼接还原的说明，不重新编码或截断原文件内容。

成功读完且没有新消息的账户，会在零点合并报告的对应行显示「无官方新消息」；有新消息的账户显示「有官方新消息」和红色图标，并另行逐条推送完整内容。读取失败、附件不完整或无法转传时会明确提示失败，不会误报为无消息。账号过多时汇总报告按机器人消息长度分段。

官方消息报告仅随已在零点启动的流程运行，不会在服务启动、页面刷新或机器人空闲时扫描。关闭 Bot 通知或未配置目标时跳过官方消息读取，原账户状态检测仍照常执行。已启用的零点报告与状态报告一样不受静默时段阻挡；大量消息、媒体上传和 Telegram 限流可能使推送在零点后继续完成。更改通知目标或关闭通知会停止旧目标的后续发送。临时下载在发送、失败或取消后清理，不保留原消息和媒体档案。

## 机器人编号查询

向已启用的私人机器人发送 `/me`，会按账号名称的自然顺序显示编号、名称和备注，例如：

```text
1. account1 — 无备注
2. account2 — 工作
3. account10 — 无备注
```

发送 `/code 2` 即可查询清单中第 2 个账号最近 5 分钟内的 Telegram 验证码，也可继续使用 `/code 账号名`。编号对应上次完整收到的 `/me` 清单；账号增删后可重新发送 `/me` 更新清单。清单中的账号已被移除时不会改查其他账号，机器人会提示更新清单。重启服务或更换 Bot/目标 ID 后需重新发送 `/me`。

45 秒冷却只限制重复的同一条完整指令：`/me` 后可以立即发送 `/code 2`，`/code 2` 后也可以发送 `/code 3`，但 45 秒内不能再次发送 `/code 2`。机器人正常接收消息后会立即处理，网络异常或 Telegram 连接建立仍可能延迟实际结果。空闲时不会检测账号或扫描验证码历史。
